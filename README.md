# TypeScript MVC Web App

A web application built with **plain TypeScript** (no framework), organized with the **MVC** pattern, for registering stock trades (date, quantity and value) and displaying them in a table. Trades can be typed into a form or imported from a separate **Express API**.

Study project based on Alura's TypeScript course.

## Features

- Register trades through a form and list them in a table
- Accept form trades **only on weekdays** (`DiasDaSemana` enum)
- Form validation with feedback messages
- **Import trades from the API**, skipping those already in the list (same day, quantity and value)
- Error message when the import fails
- HTML escaping of feedback messages to prevent injection (XSS)

The API sends no date, so imported trades get the current date, and the weekday rule does not apply to them. The list is kept in memory and is cleared when the page is reloaded.

## Structure

```
├── app/
│   ├── src/                 # Source code in TypeScript
│   │   ├── controllers/     # NegociacaoController: handles user actions and updates views
│   │   ├── decorators/      # domInjector and logarTempoDeExecucao
│   │   ├── models/          # Negociacao (a single trade) and Negociacoes (the list)
│   │   ├── services/        # NegociacoesService: fetches trades from the API
│   │   ├── views/           # Generic abstract View<T> + NegociacoesView and MensagemView
│   │   ├── enums/           # DiasDaSemana
│   │   └── app.ts           # Entry point: wires the form and the import button to the controller
│   └── dist/                # What the browser loads
│       ├── index.html, css/ # Not generated by the build
│       └── js/              # Generated by tsc (do not edit)
└── servidor-api/            # Back end in Node.js + Express (GET /dados route)
```

Front end and back end are independent projects, each with its own `package.json`.

## Getting started

Run each part in its own terminal, starting from the project root. The form works on its own; the **Importar** button also needs the API.

**Front end** (compiles in watch mode and serves `app/dist` with lite-server, at `http://localhost:3000`):

```bash
npm install
npm start
```

**API** (`http://localhost:8080/dados`):

```bash
cd servidor-api
npm install
npm start
```

## Decorators

Both use the **standard TypeScript 5+ decorators**, so `experimentalDecorators` is not needed.

| Decorator | Applies to | What it does |
|---|---|---|
| `@domInjector(selector)` | `accessor` properties | Looks up the DOM element on first access and caches it. Throws an error if nothing matches the selector |
| `@logarTempoDeExecucao(inSeconds?)` | methods | Logs how long the method took, in milliseconds (default) or seconds. For `async` methods, it only measures the time until the Promise is returned |

```ts
@domInjector('#data')
private accessor inputData: HTMLInputElement;

@logarTempoDeExecucao()
adiciona(): void {
    // ...
}
```

## TypeScript concepts covered

- Access modifiers (`public`, `protected`, `private`) and `readonly`
- Parameter properties (fields declared in the constructor)
- Getters and defensive copies (`Date`)
- Read-only arrays (`readonly Negociacao[]`)
- Generics and abstract classes (`View<T>`)
- Inheritance with `extends`
- Polymorphism: each view implements `template()`, called by the inherited `update()` (Template Method pattern)
- Decorator factories, method decorators and auto-accessor decorators
- Interfaces to describe API data
- `async`/`await` and `fetch`
- Enums
- `tsconfig.json` options (`outDir`, `rootDir`, `noImplicitAny`, `noEmitOnError`)

## My changes

- API server migrated from **CommonJS to ES Modules** (`import`/`export`), with `body-parser` replaced by Express's built-in `express.json()` and a simpler server startup
- Standard decorators instead of the legacy `experimentalDecorators` syntax
- Dates parsed in the **local time zone** (avoiding the UTC shift of `new Date('yyyy-mm-dd')`)
- Form fields validated before creating a trade
- `escapar()` helper in the base `View` class to escape HTML
- Guard clauses in `app.ts` that fail with a clear message if the form or the import button is missing
